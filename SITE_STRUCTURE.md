# Карта проекта LevelUp

Этот документ описывает структуру сайта `gamemaster.cc` и служит инструкцией для создания аналогичного проекта на другом домене. Его удобно хранить вместе с исходниками: тогда новый лендинг можно собрать без восстановления логики по памяти.

## 1. Что представляет собой проект

LevelUp — статический сайт на HTML, CSS и JavaScript без сборщика и без серверной части для каталога. Он публикуется как GitHub Pages и использует внешние сервисы только для входа в аккаунт и Steam-аутентификации.

Основная схема:

```text
index.html
├─ промо и каталог
├─ личный кабинет (всплывающее окно)
├─ интерактивы: мини-игра, 3D-визуализации, глобус
└─ ссылки на документы и полный кабинет

cabinet.html     → расширенный личный кабинет
product.html     → страница конкретного товара
legal pages      → политика, правила, контакты, ответственность
Steam Worker     → безопасная проверка Steam-входа
Firebase Auth    → Google-вход и пользовательская сессия
```

## 2. Страницы сайта

| Файл | Назначение |
| --- | --- |
| `index.html` | Главная страница: кампании, каталог, объяснение процесса, мини-игра, регионы и контакты. |
| `cabinet.html` | Полный личный кабинет: заявки, транзакции, поддержка и эмуляция оплаты. |
| `product.html` | Детальная страница выбранной игры; получает ID товара из URL. |
| `privacy.html` | Политика конфиденциальности. |
| `service-rules.html` | Правила обслуживания. |
| `contacts.html` | Реквизиты и каналы связи. |
| `responsibility.html` | Раздел об ответственности. |
| `steam-callback.html` | Техническая страница возврата после Steam-входа. |

## 3. Главная страница: порядок блоков

В `index.html` блоки идут в следующей последовательности:

1. Шапка: логотип, навигация, языки, валюта, вход в кабинет.
2. Первый экран с промо GTA VI и информационным статусом.
3. Бонусная система LevelUp и статусы игроков.
4. Узкий промо-баннер GTA VI в каталоге.
5. Каталог: быстрые подборки, поиск, фильтры, 30 игровых карточек, кнопки «Подробнее» и «В корзину».
6. «Просто и прозрачно»: четыре шага и 3D-знак вопроса.
7. Мини-игра `LevelUp Run`: пиксельный раннер с кнопкой «Прыжок».
8. География: интерактивный глобус и регионы присутствия.
9. Контактная информация и реквизиты.
10. Футер со ссылками на документы.

Если нужен похожий сайт на новом домене, эту структуру можно оставить без изменений, а заменить тексты, игры, визуальные баннеры, контакты и юридические данные.

## 4. Основные файлы и зоны ответственности

| Файл | За что отвечает |

## 5. Каталог и обложки

### Данные

Каждая карточка описана в `catalog-data.js` в таком порядке:

```js
[id, title, offer, category, platform, publisher, region, price, description, badge]
```

Чтобы добавить игру, добавьте новую строку в этот файл. Для корректной работы фильтров должны быть заполнены `category`, `platform`, `publisher` и `price`.

### Визуальные обложки

Индивидуальные обложки главного каталога размещаются в:

```text
assets/game-slots/catalog/
```

Для 30 действующих игр используются файлы формата `*-card-v2.png` (у FC — `fc-card-v3.png`). Сопоставление номера карточки и изображения находится в `styles.css` в правилах `.slot-card:nth-child(...) .slot-cover`.

Важный приём оформления: для карточек 3–30 CSS использует одну обложку дважды — как фон и в псевдоэлементе `::before` с `background-size: 108% auto`. Благодаря этому изображение заполняет всю ширину и не показывает тёмную подкладку по краям.

При замене обложки:

1. Подготовьте горизонтальный PNG примерно `960 × 420` px.
2. Сохраните его в `assets/game-slots/catalog/` под новым именем.
3. Обновите три CSS-правила для нужного номера: основной фон, `::before` и список `::after`.
4. Проверьте карточку на широком и мобильном экране.

## 6. Личный кабинет и данные пользователя

### Что работает сейчас

- Google-вход через Firebase Authentication.
- Steam-вход через Cloudflare Worker и Firebase custom token.
- Профиль, статус игрока, заявки, корзина и история в интерфейсе.
- Локальное хранение части заявок в браузере пользователя.

### Важное ограничение

Заявки и эмуляция оплаты сейчас не являются реальной платёжной системой: часть данных хранится локально в браузере. Для реальных продаж нужны серверная база данных, полноценная корзина заказов, платёжный провайдер, проверка оплаты на сервере и юридическая проверка процессов.

## 7. Внешние сервисы и что менять на новом домене

### Firebase

Конфигурация находится в `firebase-auth.js` и `steam-auth.js`. При копировании проекта безопаснее создать отдельный Firebase-проект.

Нужно:

1. Создать новый Firebase project.
2. Подключить Web App и вставить его публичный `firebaseConfig` в оба файла.
3. В Firebase Authentication включить Google provider.
4. В разделе Authorized domains добавить новый домен и его `www`-версию, если она используется.

### Steam через Cloudflare Worker

Код Worker расположен в `steam-worker/`.

| Файл | Назначение |
| --- | --- |
| `steam-worker/src/index.js` | Логика Steam OpenID и выдачи Firebase custom token. |
| `steam-worker/wrangler.toml` | Имя и адрес Worker. |
| `steam-worker/README.md` | Инструкция по развёртыванию и секретам. |

При новом домене нужно обновить:

- адрес Worker в `firebase-auth.js` и `steam-auth.js`;
- разрешённые callback URL и origin в Worker;
- URL сайта в настройках Worker;
- настройки Firebase для нового домена.

Никогда не коммитите сервисный ключ Firebase, токены Cloudflare или другие секреты. В репозитории должны остаться только публичные настройки и шаблоны.

## 8. Домен и публикация

Сайт рассчитан на GitHub Pages.

Для нового домена:

1. Создайте новый репозиторий или сделайте копию существующего.
2. В GitHub Pages включите публикацию из ветки `main`, папка `/ (root)`.
3. Измените файл `CNAME`: в нём должен быть только новый домен без `https://`.
4. У регистратора добавьте DNS-записи GitHub Pages: четыре `A`-записи для корня домена и `CNAME` `www` на `<github-user>.github.io`.
5. В GitHub Pages укажите Custom domain и дождитесь проверки DNS/HTTPS.
6. Обновите домен в `robots.txt`, `sitemap.xml`, мета-тегах и настройках Firebase/Worker.

## 9. SEO и технические файлы

| Файл | Назначение |
| --- | --- |
| `robots.txt` | Правила сканирования и ссылка на sitemap. |
| `sitemap.xml` | Список основных страниц для поисковых систем. |
| `yandex_b1460a579684be7b.html` | Подтверждение права на сайт в Яндекс Вебмастере. |
| `CNAME` | Подключаемый домен для GitHub Pages. |

При новом домене обязательно замените старые URL в `robots.txt` и `sitemap.xml`. Файл подтверждения Яндекса потребуется выпустить заново для нового сайта.

## 10. Ассеты

```text
assets/
├─ brand/       логотип, favicon и элементы бренда
├─ hero/        главный промо-баннер
├─ banners/     узкие промо-баннеры
├─ bonus/       визуал бонусной программы
├─ games/       ранние игровые изображения
├─ game-slots/  фоны и 30 индивидуальных обложек каталога
├─ globe/       текстура Земли
└─ ...
```

Для нового бренда в первую очередь заменяются `assets/brand/`, `assets/hero/`, `assets/banners/`, контакты и юридические данные. Каталог и интерактивы можно оставить как основу.

## 11. Безопасный порядок создания копии

1. Скопировать проект в новую папку и создать новый GitHub-репозиторий.
2. Переименовать бренд, заменить логотип, контакты и юридические документы.
3. Настроить новый домен и GitHub Pages.
4. Создать отдельные Firebase project и Cloudflare Worker.
5. Подключить новые домены к Firebase/Steam Worker.
6. Заменить каталог, цены, валюты и обложки.
7. Обновить `CNAME`, `robots.txt`, `sitemap.xml` и SEO-мета-теги.
8. Проверить Google-вход, Steam-вход, все ссылки, языки, валюты и мобильную версию.
9. Только после серверной интеграции подключать реальную оплату.

## 12. Рекомендуемое имя для копии

Если задача — похожий сайт под другой проект, лучше не копировать LevelUp буквально. Оставьте технический каркас, но используйте новое имя, лого, палитру, тексты и собственные изображения. Так проект будет быстрее адаптировать и легче развивать отдельно.
